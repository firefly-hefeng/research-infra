02

外部规范：成员共同遵守的规则

存放、提交与使用

  1. 登记身份与存储位置分开。两类公共库完整编目；只有核验通过的迁移才更新当前位置，旧路径兼容另行记录。日常编目不为套用结构搬文件或改权限，成员工作区不纳入。
  2. 新资料先有说明，再进入正式库。未来每次增补提交资料与 README；服务器侧 CLI/SFTP/rsync 为主，网页小文件入口可选。当前先下载模板准备，不开始传输。
  3. 来源和使用条件如实写。写明官方来源、资料责任方或采集/产生方式；许可证未知就写未知。团队公共区不等于可向外部公开下载。
  4. 提交者与维护人分开。贡献者负责说明本次提交；维护人承担长期说明、版本与使用问题的维护责任。Unix owner 只是系统属性，不自动成为维护人。
  5. 发布版本不覆盖。数据、标签、正式 split 或权重变化就新建内容版本；仅修正文案增加 metadata_revision，保留变更记录。
  6. 保留原始与派生关系。原始输入不原地改写；处理结果说明输入版本、代码 revision、参数与输出。无法确认的关系不由文件名推断。
  7. 同源副本不当成新资源。同一版本的多处存储记录为 locations；仅凭同名不合并，仅凭摘要相同不自动删副本。
  8. 引用稳定 ID 和版本。实验记录资源 ID、版本、实际子集与处理配置，不只写一个可变目录名或 latest。
  9. 只在授权范围内读取与分发。restricted 表示当前账户读不到，不自动 chmod 或提权；模型可下载、可加载和可再分发分别判断。
  10. 大任务单独安排。整库迁移、删除、物理去重、格式转换、特征重算与训练不混入日常编目；符合已批准规则的小范围新版本可自动发布。

目录与 README 的采用方式参考 MIT 文件组织建议；本机规则按现有两公共根与低影响运行要求适配，并非复制其内部基础设施。

新资料的目标结构 · 实际状态以回执为准

两个内容根，一个增补区

/data/share/
├── datasets/<slug>/releases/<version>/
│   ├── README.md          数据卡：YAML 元数据 + 人类说明
│   ├── manifest.jsonl     机器生成的文件清单与摘要
│   └── content/           内容，尽量保留上游内部结构
├── models/<slug>/releases/<version>/
│   ├── README.md          模型卡
│   ├── manifest.jsonl
│   └── content/
└── incoming/<submission-id>/    设计中，尚未创建
    ├── README.md          增补提交说明
    ├── manifest.jsonl     提交工具生成的清单
    ├── content/
    └── READY.json         提交编号、清单摘要与完成时间

命名约定

slug 用小写字母、数字和连字符，保持简短可读；版本用 v001 或安全短名，上游 revision 另存。不要使用“最终版”“最新版2”等无法稳定引用的名称。

稳定资源 ID 不等于 slug、路径或哈希。目录名改变不应改变资料身份；填写模板不触发改名，已授权迁移按独立事务与回执执行。

内部内容结构

不要求将所有资源强行改成同一种文件格式或巨型 raw/processed 树。原始/派生性质写入版本元数据，具体文件结构在卡片中解释。

模型缓存可能引用内部 blobs；不能只移动 snapshot 破坏链接。清单和目录规范不代替实际内容检查。

当前路径、计划位置与兼容路径分别记录

上述结构是未来正式发布布局，不是当前已完成部署清单。canonical 目标为 /data/share/datasets 与 /data/share/models；当前复制尚未完成，/data/datasets 与 /data/models 仍是来源，核验切换后才成为兼容别名。复制中、受阻或仅有目标目录均不表示完成。同一共享资料不计作三份资产；另两台节点的实际挂载与身份映射尚未登录核验。实际位置与主机核验见 存储状态；日常 Agent 不自动调整成员正在使用的路径。

严格定义，允许诚实地保留未知

README 机器元数据

README 顶部 YAML 安全解析为 JSON 兼容对象，再按 Resource Card Schema 校验。规范元数据只有这一个真源；SQLite、JSON/CSV 导出与前端均为投影。当前快照/sidecar 仍是过渡数据，不能声称已完成真源切换。

字段分组；全部子字段与条件见可下载字段规范和 Schema
字段必须表达的内容关键约束
schema_version / profile结构版本 1.0；draft、legacy 或 release。profile 不是上传状态；legacy 固定 observed。
resourceID、slug、名称、类型、简介、任务、标签、旧 ID。ID 稳定；类型包括 dataset/model 与必要的集合、特征、标签等。

rights元数据共享、团队使用、外部分发、许可证和证据。团队公开 ≠ 外部分发许可；三项分别记录。
locations / relations主机、路径、位置角色、访问观察；派生、微调、替代或训练关系。关联以证据建立；副本是位置，不重复建立资源。

manifest清单路径、清单摘要、内容覆盖级别、文件数、字节数与时间。完整性有明确范围；清单摘要不替代数据文件摘要。

通用类型规则

日期采用带时区的 ISO 8601 字符串。未知标量写 null，未知枚举写 unknown；0 只代表有依据的零值。空列表是尚未记录，不自动证明不存在。

拒绝重复键、非有限数值、危险 YAML 标签和未定义字段。字段名与枚举由 Schema 明确，不靠模糊字符串约定。

Schema 之外仍要检查

真实来源、权利、维护责任、跨字段关系、规范化路径、符号链接边界、完整文件清单及实际写保护，均需运行时检查。

正式 Schema 合法不等于获得发布权限，也不意味着内容可加载或已经冻结。

07

每项陈述知道自己从何而来

证据类型与校验范围

不同依据支持不同层次的结论
证据类型可以支持不能自动支持
source_document来源文档在某时刻的声明。当前路径可读或内容未变化。
upstream_metadata上游配置、数据卡或模型卡的描述。本机实测性能和硬件需求。
filesystem_observation观察到的路径、大小、文件类型和账户访问结果。完整性、版权许可和维护责任。
maintainer_statement责任人确认的归属、用途或许可依据。不相关第三方权利已经得到授权。
computed_checksum明确范围与时间的内容摘要。范围之外的完整性或语义等价。
processing_record输入版本、代码、参数与输出的处理关系。没有记录的处理步骤或因果保证。
文件观察不替代科研判断

stat 成功不等于内容完整；权重存在不等于加载成功；上游性能不是本机评估；目录个数不是参与者人数。冲突证据并列保留，unknowns 记录原因与下一步。Agent 的解释必须指向依据，不是另一份独立事实证据。

manifest.jsonl 的精确定义

每行一个 JSON 对象，path 相对 content/，按路径排序并保持唯一。普通文件记录字节数与 SHA-256；未校验为 null。空目录可单独记录。符号链接记录相对目标，运行时解析后的目标必须留在同一 content 边界。

link_target 可有合法的 ..，但清单条目的 path 不可越界。full 表示声明范围全部列出且普通文件均有可验证摘要；manifest_sha256 只校验清单文件本身。示例清单是虚构空文件，不是服务器扫描结果。

08

未来流程设计 · 当前没有上传或调度

一个增补区，同一条整理流程

原位登记 register

成员填写有证据的公共资料位置：复制期间记录旧根来源，核验切换后采用 CPFS canonical，旧根作为兼容引用。流程只整理说明和身份映射。未知字段待补充，资料保持 observed；不复制、不改权限、不移动。

新资料接入 transfer

未来流程分配增补编号和容量预约，成员用 CLI/SFTP/rsync 写入 /data/share/incoming/<submission-id> 专有位置；该增补根尚未创建，接收尚未启用。前端接入同一个提交记录和说明状态，网页大文件上传不是前提。

  1. draft准备资料和说明
  2. submitted完成标记已确认
  3. validating结构、边界与内容检查
  4. needs_information缺失或冲突待处理
  5. ready符合规则可发布
  6. publishing原子发布与对账
  7. published正式版本可引用

needs_information 是条件分支，不要求所有提交都经过人工确认。模板中的 ready 布尔值只是工具维护的提交完成展示字段，不等于校验后的 ready 任务状态。当前页面和模板不会启动任何传输或调度。

READY.json：完成标记、接手回执与重试协议

提交工具确认传输结束并关闭写入文件，生成最终 manifest.jsonl；随后计算其原始字节的 SHA-256，将临时标记原子改名为 READY.json。标记只含工具生成的 submission_id、manifest_sha256、submitted_at，分别为分配编号、清单摘要和带时区完成时间。见 精确 JSON 示例及 Schema。

Agent 核对标记、身份与清单摘要，以编号和清单摘要原子登记任务接手，并返回回执/状态；标记本身不是接手回执。同一编号和摘要重试返回同一任务，不重复发布；同一编号换摘要视为冲突。内容变化需新提交编号，说明更正需显式修订记录，不能静默覆盖接手证据。

完成标记不会冻结打开的文件。上传者必须停止所有写入；未来实现还需可验证的暂存隔离或稳定快照，再核对实际文件集合和内容摘要，发布前确认未漂移。仅改权限或重命名目录无法阻止已打开文件继续写入；无法确保稳定时停止发布。原位登记仍为 observed，不据此改原文件权限。完整运行时约束见 字段与执行规范。

Agent 的自动边界
可按已批准规则自动执行进入待处理或另行讨论
检查最小说明、验证 Schema、分配稳定 ID、原位登记、生成清单、在预算内校验、提示重复候选；条件全部满足的新版本可以自动发布。授权或来源冲突、语义不清、疑似重复需要合并、覆盖旧版本、旧路径迁移、删源或去重、整库重排、大体量处理、转换格式、特征重算或训练。

自动发布仍需身份有效、维护责任与团队使用依据明确、路径安全、不覆盖旧版本、校验成功、容量足够且无冲突。新内容的发布事务与文件切换需要中断恢复；取消只能清理本次专有暂存，不能删除原位来源。

共享盘并发下载、发布隔离和挂载失效保护见 CPFS 团队规范；当前 NFS 挂载不能靠 flock 充当全组下载锁。未来定期整理只处理完成提交，不遍历所有成员目录。具体周期、限速、配额与运行窗口后续确认；本轮不创建自动化，不创建 /data/share/incoming。

已有工作继续可用

现有原位卡片如何过渡

  1. 现在原位记录

    保留目录快照与 sidecar

    它们说明目前知道的路径、来源和访问状态。既有记录不是冻结版本；README 真源还没有逐项落地。历史登记保留，实际位置按独立存储清单更新；观察时间与卡片生成时间分别展示。

  2. 逐项整理规范映射

    确认身份、来源与责任

    建立旧 asset ID 到稳定 resource ID 的映射，保留真实路径；未知维护人不从 owner 推断。先在项目侧形成卡片，不向原目录擅自写入文件。

  3. 正式采用单一真源

    按资源明确切换

    资源转入 README 模式后，规范字段从 README 读取；旧快照和 sidecar 仅作为历史证据，不再反向覆盖。数据库投影可重建，卡片随资料保存。

内容迁移独立执行，状态以核验清单为准

已批准的 CPFS 迁移需逐项记录目标、复制与校验结果、切换、旧路径兼容和回退安排。未切换条目继续使用原路径，历史访问观察不能代替新位置核验。旧元数据修订与存储切换都不自动改变内容版本，也不能自动提升 content_frozen。

文档有效，不等于能力已经运行

校验与采用标准

本轮文档检查

  • 链接、锚点、下载文件和 ZIP 内容能够对应。
  • HTML 不包含脚本或内联样式，仅引用本地 CSS。
  • JSON Schema 符合 Draft 2020-12；README YAML、JSON/JSONL 示例可解析且符合 Schema。
  • 示例声明虚构；来源链接来自官方一手资料，采用原则与本地规则明确对应。
  • 原位过渡、未知许可、维护人身份和未启用接入的界限一致。

未来实现还需验证

  • 安全 YAML 解析、路径规范化与符号链接边界。
  • 证据引用完整、来源/许可与维护责任真实有效。
  • READY.json 与清单绑定、接手回执、内容稳定性和幂等重试。
  • 容量预约、配额和取消回收。
  • 清单完整性、版本不可覆盖、发布中断恢复。
  • SQLite 可由 README 重建；规则内自动发布与异常转处理分别有效。

规范采用 JSON Schema Draft 2020-12。启用格式校验时检查 date-time；Schema 无法单独证明文件系统边界、证据真实性和内容冻结，这些必须留在运行时验收中。
