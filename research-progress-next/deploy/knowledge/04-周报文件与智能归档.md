# 周报文件与智能归档

提交页的“已收原件、已入汇总、待整理”代表不同阶段，不等同于研究完成度。

## 处理流程

1. **接收原件**：选择成员和周次，上传一个文件。扩展名不限，默认上限 20 MiB；原件以摘要做幂等校验，不公开下载，也不会被执行。
2. **内容提取**：标准 Markdown 直接校验；UTF-8 文本、DOCX、PPTX、XLSX、PDF 和图片进入自动处理。其他格式保留原件并转人工整理。
3. **Agent 整理**：DeepSeek 将可解析内容整理为“本周完成、结果与证据、问题与阻塞、下周计划”。系统要求严格 JSON，并再次检查成员、周次、栏目和长度。
4. **进入进度**：校验通过后写入个人正式周报并触发团队汇总。待整理文件不会作为已正式提交的内容进入研究结论。
5. **失败保护**：解析失败、模型异常或与已有正式周报冲突时，旧报告和原件均保留，状态明确显示，不自动覆盖。

## 状态含义

- `queued`：原件已保存，等待定时整理。
- `processing`：正在提取内容和智能归档。
- `ready`：已通过模板校验，可以进入团队汇总。
- `needs_review`：格式无法可靠解析、内容为空或存在冲突，需要维护人员处理。
- `failed`：模型或处理流程失败，可检查配置后重新排队。

## 团队进度口径

“已入汇总”统计已经规范化的正式周报；“已收原件”还包括仍在整理或待复核的文件；“未提交”仅表示没有收到任何原件。待整理不代表没有开展研究，也不应被模型补写为研究成果。

## 隐私与更正

不上传密码、密钥、受试者身份或无关敏感文件。原始文件不开放 HTTP 读取。相同文件重复上传幂等成功；同周不同文件或不同内容返回冲突，由维护人员备份后处理。
