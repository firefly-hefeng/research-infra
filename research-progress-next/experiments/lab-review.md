# 阶段复盘与项目盘核对

日常看团队页近 28 天的研究全景。周会或阶段评审需要跨周核对时，使用 `research_weekly.lab_review` 汇总已归档报告，并按需要纳入成员项目空间里可供团队及模型阅读的实验记录。每次独立输出一个版本。

| 读者的问题 | 复盘中的证据 |
| --- | --- |
| 实验室现在能下什么判断，下一次周会需要决定什么？ | 跨方向的进展、结果、限制和验证优先级，逐条可展开 |
| 被讨论的是哪个问题？ | 研究主题可引用已有方向 ID；新问题出现在本期主题中，保留成员和来源 |
| 具体是谁做到哪一步？ | 按成员展开四栏与原文摘录，沿原报告链接回到团队时间表 |
| 有没有漏读？ | 查看输入起止、成员、来源清单、扫描根目录、无法读取或超限的记录数 |

## 在服务器生成

在进度模块目录，复用该服务的 Python 环境。每个项目根单独给出绝对路径和登记成员 ID，`include_files` 列出逐项核对过的共享文档，例如 `["README.md","docs/实验结果.md"]`。目录、文件与归属映射有误时先修正清单。定时复盘只处理明确列出的项目文件。手动运行省略此字段时会在指定目录内按研究记录文件名扫描。

目录归属只用于核对读取范围。成员栏引用署名日报和周报；项目盘材料另列，供方向和实验室复盘引用。正式方向必须在本主题的原文摘录中出现登记名称、ID 或已核对的同题名称。仅有数据集重名或参考基线时，保留为本期研究主题。

项目材料默认用于内部复盘。已确认可供全员阅读的目录清单须另标 `audience: "team"` 才能接入周报后的自动复盘。内部报告、引用内部项目原文的报告，以及项目来源共享范围未标明的报告，团队网页均拒绝展示。

成员原定计划与模型建议分别标注。引用或综合基线需要与完成复现区分；比较公开目标数值时应保留评估协议、数据切分与分母。对于模型无法可靠判断的关系，按原件人工核对。

```sh
python -m research_weekly.lab_review --server-config config.server.json --roots member-projects.json --inventory-only --output inventory-2026-W47.json
python -m research_weekly.lab_review --server-config config.server.json --roots member-projects.json --output review-2026-W47.json
python -m research_weekly.lab_review_page review-2026-W47.json review-2026-W47.html
```

第一条只做来源核对。第二条读取正式归档中所有日期的规范日报、周报，以及指定项目根的 README、进度、结果和实验类 UTF-8 文档。项目代码、音频、患者原始资料、模型权重和附件不送入模型。目录和正文遇到 TFBS 标识时排除，避免把何锋要求排除的研究带入任何一级摘要。编码不匹配、读取失败和单篇超过 200,000 字节会计数；文件的修改时间不能单独证明实验进展。JSON 保留扫描范围与内容哈希，服务器绝对路径仅供内部复核。

模型从进度服务的既有配置读取模型名、推理强度、服务地址、凭据环境变量名与远程处理许可。模型按来源批次先整理成员工作，再归纳研究问题和实验室判断。程序从原件确定证据编号和逐字摘录。行文判断仍需核对证据是否足以支持结论。运行失败时保留此前发布的版本。

也可将浏览器授权读取的共享报告 JSON 作为首个位置参数替代 `--server-config`。JSON 含 `members[{id,name}]`、`directions[{id,title}]`、`sources[{id,kind,member_id,title,sha256,url,content}]`，可附 `source_window`；只有被读取的来源会计入覆盖。没有 `--roots` 的结果明确显示实际扫描项目目录数为零。

内部项目盘先盘点，再在获准处理内部材料的环境中运行。以下两步使用同一份受限证据包。结果及缓存放在与输入具有同等访问限制的工作目录；团队作业使用自己独立的证据清单。

多个服务器挂载同一存储时，分别记录观测点，按原件路径和正文指纹去重。周会读取现行 README；同一文件的 `README.before-*` 快照保留作版本溯源。若从盘点到真正取文之间正文变化，记录两次指纹，并使用已读取版本核对摘录行号。资产迁移、标签验收和训练恢复分别记录；要形成新的个人或模型结论，仍须有对应署名和评估证据。

```sh
python -m research_weekly.lab_review internal-evidence.json --inventory-only --output private/inventory.json
python -m research_weekly.lab_review internal-evidence.json --model-config config.server.json --cache-dir private/cache --output private/review.json
```

## 供成员和 Agent 阅读

成员提交或更正日报、周报后，已有收件任务每分钟检查一次。近 28 天研究全景在来源变化后重新整理，实际可见时间取决于模型响应、证据检验和重试。周一的阶段复盘另由 `lab_review.weekly` 开启；`lab_review.project_roots` 仅填逐文件核实的团队项目清单。

人工校审稿是默认读本，原始来源与成员名册相同时，周任务直接复用。出现新材料后，单独写入 `lab-review-auto.json`，在校审稿页显示「阅读新材料的自动复盘」。新人工稿发布后，旧自动稿的链接失效。成员、方向或模型配置变动可以触发自动稿更新。对已校审且来源、名册相同的版本，优先保留校审结论。已核实的提取批次存在私有状态目录中，正文、栏目、来源或模型配置改变时重新提取。一次任务失败不影响已有周报和复盘。

保留带日期的核验版本。用已核对的结果在团队目录原子更新 `lab-review.json` 后，下一次团队页刷新会在研究全景上方显示「阅读阶段复盘」。进度服务启用团队共享时，`GET /progress/api/lab-review` 返回人类可读的 HTML。页面只展示报告文字、摘录、原报告链接与覆盖，不展示服务器私有路径。Agent 可在已授权服务器读取同一版 JSON。成员仍通过原来的日报和周报入口提交。

飞书会话读取 `?format=json` 时，实验室每条判断的 `related_topic_keys` 指向主题的 `key`。两个层级须同时引用同一个来源 ID 和相同的引文。主题的 `report_member_ids` 仅来自所引日报和周报的署名；成员的 `cited_in_topic_keys` 给出反向查询。列表为空表示本版缺少相应直接引文。原有 `direction_id` 继续表示已经核实的正式方向归属。新增导航在读取时生成，无须再次调用模型。

### 工作量与复用

对已审核的 30 份署名报告离线盘点，正文计 16,601 个字符。8 批成员提取加 1 次实验室汇总，首次顺利完成需 9 次请求，若各阶段均用满格式重试则最多 27 次。字符数只统计原文，提示词、引用包装、推理及回答均需额外 token。旧运行未留下服务商计量，历史实付金额无法复原。

新版本在结果的 `model_usage` 中记录实际请求数、耗时、复用的批次和服务商返回的 token 小计。缺失计量的响应单列计数，金额以实际账单为准。已校审且输入无变化时调用数为 0；若已有 8 位成员的有效提取缓存，只改 1 人的一批报告时，顺利完成通常为 1 次提取加 1 次汇总。该增量行为已用证据编号发生变化的独立用例验证。

防覆盖版在 Linux 通过进度模块全部 158 项测试。在最新实机源码前像上验证了 12 个文件加 1 项配置的安装、完整回退、并发编辑保留和实际网页入口，并在 1440、390、320 像素核对两个版本的链接。全员发布包只内含已核验的署名报告。安装候选及指纹见[发布清单](../../var/releases/2026-11-21/SHA256SUMS)。
