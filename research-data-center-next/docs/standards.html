本轮的实际边界

当前为规范与接收协议 2.0：实现受限规则接收与 Agent 接口，生产是否启用以部署回执为准；默认校验和计划，管理团队精确授权后发布。不提供模型服务或 LLM 执行器；规则周期启用后约每五分钟检查，仅发布精确授权任务。现有目录记录是原位卡片，不是已冻结版本。存储迁移是另行执行与核验的工作；此规范页不表示迁移已完成，也不授权更改权限或干扰运行任务。

只讨论阿里云本机主力库。公共区内所有内容均编目，未知许可、混合用途或权限不足不构成删除目录条目的理由；来源许可、当前可读性与外部分发权单独标注。实际目录与覆盖范围查看 当前摘要。

02

成员共同遵守，管理团队负责完善

使用者交资料，管理团队维护规范

  1. 使用者只填最小说明。名称、来源、用途、内容、使用限制五项 README，配合本人 incoming 中的 payload；不要求填写完整 dataset/model 卡、目标版本或人工哈希。
  2. 管理团队维护正式卡。稳定身份、研究背景、使用说明、证据、维护责任、版本和发布目标由管理团队整理并持续维护；不把提交者或 Unix owner 自动当成维护人。
  3. 来源与许可据实写。unknown 可登记待补，不能猜测为开放许可。团队公共区不等于允许外部分发。
  4. 只写本人的增补入口。incoming 根 root:ml-readers 2755；管理员预建本人:992 的 2750 bucket，文件0640/目录2750，rmp 同组只读。缺入口联系管理团队，不自行扩权、不接管他人 public 目录。
  5. 版本和来源保留。正式内容不覆盖旧版本，重复登记不重复复制；原始提交不因失败、重试或未来撤回而自动删除。
  6. 大任务和语义歧义另议。自动流程默认校验和计划；明确 policy 与目标授权才可发布。迁移、去重删除、合并、解压、转换和训练不在通用执行范围。

正式资料的长期布局

管理团队完善后，新正式版本采用 /data/share/{datasets,models}/<slug>/releases/<version>/{README.md,manifest.jsonl,content/}。当前 worker 的 managed 接收收据不冒充该完整卡。

既有目录按原登记和迁移回执展示，不为套用结构自动搬文件；同一版本多副本记录为位置，不新增身份。

cold 不是活动文件系统

/data/share_cold 实测为 ossfs/FUSE，不能假定原子 rename 或可靠跨机 flock。写唯一对象后读回核验，再记录完成回执；不在 cold 运行 SQLite 或直接执行脚本。

仅一个 coordinator 在本机裁决任务；成员实验继续使用已有 public 工作区，不被系统接管。

计划位置不等于实际部署

新接收工具和运行布局是否启用，以服务状态和部署验收为准。原两库迁移仍由独立事务维护，是否切换、旧根是否成为兼容软链只认生产回执。

06

严格定义，允许诚实地保留未知

README 机器元数据

README 顶部 YAML 安全解析为 JSON 兼容对象，再按 Resource Card Schema 校验。规范元数据只有这一个真源；SQLite、JSON/CSV 导出与前端均为投影。当前快照/sidecar 仍是过渡数据，不能声称已完成真源切换。

字段分组；全部子字段与条件见可下载字段规范和 Schema
字段必须表达的内容关键约束
schema_version / profile结构版本 1.0；draft、legacy 或 release。profile 不是上传状态；legacy 固定 observed。
resourceID、slug、名称、类型、简介、任务、标签、旧 ID。ID 稳定；类型包括 dataset/model 与必要的集合、特征、标签等。
release本地版本、上游 revision、original/derived/mixed/unknown、保证状态和元数据修订。源版本、内容版本、说明修订不混用。
maintainer / sources实际认领的维护人、联系渠道；来源定位、上游版本与获取时间。维护人不等于文件系统 owner；未知来源保留待办。
rights元数据共享、团队使用、外部分发、许可证和证据。团队公开 ≠ 外部分发许可；三项分别记录。
locations / relations主机、路径、位置角色、访问观察；派生、微调、替代或训练关系。关联以证据建立；副本是位置，不重复建立资源。
dataset / model数据的样本单位、split、字典；或模型的基础版本、框架、精度、加载和评估引用。对应类型对象必填；未知计数为 null，未评估不虚构结果。
manifest清单路径、清单摘要、内容覆盖级别、文件数、字节数与时间。完整性有明确范围；清单摘要不替代数据文件摘要。
evidence / field_evidence / unknowns证据本身、字段到证据的映射、未知原因与下一步。证据 ID 不悬空；冲突保留，不由 Agent 猜测裁决。

通用类型规则

日期采用带时区的 ISO 8601 字符串。未知标量写 null，未知枚举写 unknown；0 只代表有依据的零值。空列表是尚未记录，不自动证明不存在。

拒绝重复键、非有限数值、危险 YAML 标签和未定义字段。字段名与枚举由 Schema 明确，不靠模糊字符串约定。

Schema 之外仍要检查

真实来源、权利、维护责任、跨字段关系、规范化路径、符号链接边界、完整文件清单及实际写保护，均需运行时检查。

正式 Schema 合法不等于获得发布权限，也不意味着内容可加载或已经冻结。

07

每项陈述知道自己从何而来

证据类型与校验范围

不同依据支持不同层次的结论
证据类型可以支持不能自动支持
source_document来源文档在某时刻的声明。当前路径可读或内容未变化。
upstream_metadata上游配置、数据卡或模型卡的描述。本机实测性能和硬件需求。
filesystem_observation观察到的路径、大小、文件类型和账户访问结果。完整性、版权许可和维护责任。
maintainer_statement责任人确认的归属、用途或许可依据。不相关第三方权利已经得到授权。
computed_checksum明确范围与时间的内容摘要。范围之外的完整性或语义等价。
processing_record输入版本、代码、参数与输出的处理关系。没有记录的处理步骤或因果保证。
文件观察不替代科研判断

stat 成功不等于内容完整；权重存在不等于加载成功；上游性能不是本机评估；目录个数不是参与者人数。冲突证据并列保留，unknowns 记录原因与下一步。Agent 的解释必须指向依据，不是另一份独立事实证据。

manifest.jsonl 的精确定义

每行一个 JSON 对象，path 相对 content/，按路径排序并保持唯一。普通文件记录字节数与 SHA-256；未校验为 null。空目录可单独记录。符号链接记录相对目标，运行时解析后的目标必须留在同一 content 边界。

link_target 可有合法的 ..，但清单条目的 path 不可越界。full 表示声明范围全部列出且普通文件均有可验证摘要；manifest_sha256 只校验清单文件本身。示例清单是虚构空文件，不是服务器扫描结果。

08

规则执行 · 无模型服务 · 不依赖 LLM 决策

管理员接手后，先校验再按授权发布

成员 README 的“传输完成”是交接声明，不等于下面的 submitted。管理员先检查并准备合法协议文件；现有 worker 不自动把普通 README 转成队列任务。

  1. submitted完成标记已登记
  2. validating集合与内容摘要核验
  3. needs_information团队使用条件待补
  4. review_required目标、语义、预算待审
  5. ready明确内容与目标授权
  6. publishing无覆盖发布并对账
  7. published回执可查，团队完善卡片

needs_information / review_required 是条件分支，failed 保留失败原因。默认只登记与校验；计划需指定管理目标。启用规则周期后，仅精确授权的 ready 任务可自动发布；approve 将 content_digest + kind + resource_id + version 精确绑定，publish 仍核对 policy 和目标不覆盖。超限不能靠一次 approve 绕过。

READY 2.0、接手与幂等

工具生成 schema_version、user、submission_id、submission_sha256、manifest_sha256、content_digest、submitted_at、entry_count、file_count、total_bytes。content_digest 绑定说明与清单的精确字节摘要；字段见 Schema，精确示例与对应清单一同下载。

完成标记不是锁或发布批准，不能冻结仍打开的文件。提交者停止写入后，协调器仍重新核对集合和哈希；发布前后检测变化。相同编号与摘要返回同一任务，内容或说明变化需新编号；不覆盖原证据、不删除原提交。

当前受限能力未实现或禁止的扩展
明确 incoming 范围内准备/登记/校验/计划，本机单 coordinator，批准后向独占 managed 目标发布，部分完成状态按证据对账。无用户撤回/删除或模型服务；规则周期启用状态以服务回执为准；不执行输入代码、不解压、不联网下载、不自动语义合并、不处理成员 public 目录。未来 LLM 只能建议。

初版取消需求由管理团队按当前阶段处理，没有撤回 API；删除 READY 或 payload 不是取消。Agent 与前端只读接口为 /api/ingestion/manifest、/api/ingestion/status、/api/ingestion/published，管理操作只走授权 CLI。

09

已有工作继续可用

现有原位卡片如何过渡

  1. 现在原位记录

    保留目录快照与 sidecar

    它们说明目前知道的路径、来源和访问状态。既有记录不是冻结版本；README 真源还没有逐项落地。历史登记保留，实际位置按独立存储清单更新；观察时间与卡片生成时间分别展示。

  2. 逐项整理规范映射

    确认身份、来源与责任

    建立旧 asset ID 到稳定 resource ID 的映射，保留真实路径；未知维护人不从 owner 推断。先在项目侧形成卡片，不向原目录擅自写入文件。

  3. 正式采用单一真源

    按资源明确切换

    资源转入 README 模式后，规范字段从 README 读取；旧快照和 sidecar 仅作为历史证据，不再反向覆盖。数据库投影可重建，卡片随资料保存。

内容迁移独立执行，状态以核验清单为准

已批准的 CPFS 迁移需逐项记录目标、复制与校验结果、切换、旧路径兼容和回退安排。未切换条目继续使用原路径，历史访问观察不能代替新位置核验。旧元数据修订与存储切换都不自动改变内容版本，也不能自动提升 content_frozen。

  • JSON Schema 符合 Draft 2020-12；README YAML、JSON/JSONL 示例可解析且符合 Schema。
  • 示例声明虚构；来源链接来自官方一手资料，采用原则与本地规则明确对应。
  • 原位过渡、未知许可、维护人身份和接入启用条件的界限一致。

启用前与运行中继续验收

  • 安全 YAML 解析、路径规范化与符号链接边界。
  • 证据引用完整、来源/许可与维护责任真实有效。
  • READY.json 与清单绑定、接手回执、内容稳定性和幂等重试。
  • 容量预算和超限阻断；不宣称已有用户撤回/自动清理。
  • 清单完整性、版本不可覆盖、发布中断恢复。
  • 资料查询投影可由正式 README 重建；运营队列/批准/日志需独立持久备份，不能仅靠 README 恢复。

规范采用 JSON Schema Draft 2020-12。启用格式校验时检查 date-time；Schema 无法单独证明文件系统边界、证据真实性和内容冻结，这些必须留在运行时验收中。
