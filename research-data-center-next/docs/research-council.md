# 基础学术委员会与合作规则

每个方向用一份短 README，留下研究问题、联系人、最新证据和下一步。能链接现有资料，就沿用原文。方向变化时随手更新，关键历史结果按日期保留。

文献发现由三个席位共同维护。方向研究者用正在做的课题抽查检索遗漏，文献编辑对照原始题录核实题名、作者署名和阅读许可，方法评审沿图谱核对一条关系的来源字段。每次调整排序、归类或图谱规则，保留一个实际改善的检索例子和一个容易误判的反例。复用原题录和笔记记录判断，周会只讨论会改变研究计划的发现。[打开文献图谱](/papers/#graph)

| 席位 | 负责回答的问题 | 提交内容 |
| --- | --- | --- |
| 学术方法 | 问题和比较是否合理？结论基于哪个人群、数据划分和指标？ | 一条可核查的判断与依据，包含结果的适用范围 |
| 数据与模型 | 资料或模型是什么？谁可以怎样用？分类和数量单位是否准确？ | 自然语言介绍、研究分类、来源与使用边界 |
| 研究协作 | 当前做到哪里、遇到什么、接下来找谁？ | 一段方向更新，链接周报、实验或文献 |
| Agent 与文档 | 人和 Agent 能否通过同一入口找到正确信息？ | 短 README、稳定链接或可读接口，未知项直接标注 |
| 前端体验 | 同事能否快速查资料、理解成果、接续上一项工作？ | 页面检查结果与具体修正，覆盖桌面和移动端 |
| 研究负责人 | 跨方向意见冲突时采用哪条结论？涉及授权或发布时由谁承担责任？ | 适用范围和一句有日期的决定，附相关证据 |

席位是本次修订的评审分工。团队可按议题指定实际联系人，一人可以承担多个视角。日常工作由成员直接更新，遇到跨方向分类争议、临床或外部结论、共享资料授权、影响其他用户的改动时，再请对应席位复核。意见有分歧时，记下各自依据、暂时采用的处理和复核点。涉及权限和原件的操作按现有服务约定执行。

## 日常共同规则

- **写短、链接原文。** 周报和实验已有记录时，方向 README 只提炼变化和下一步。人读自然语言，Agent 可用同一份说明和稳定 ID 查来源。
- **更新事实。** 资料的存在、可读、许可和研究质量分别说明。实验结论写明输入版本、代码或配置、评估范围和证据，开发集、测试集和外部验证各自标注。
- **按需要协调。** 人员、目标和时间随研究调整。使用最新实质更新和已有周报表达进度，完成百分比和固定审核阶段由具体项目按需选用。
- **人工决定。** Agent 可草拟介绍、提取线索和检查链接。负责人维护取舍与授权，有争议时保留原证据、直接讨论。
- **独立升级。** 数据、进度、文献和服务器模块各有一个日常入口。模块改版保持现有可用链接，逐个验收日常操作和证据回查。

## 前端体验评审

成员席按真实任务检查：首页能否直达数据、团队进展、文书和算力；资料页能否由大类找到小类和原记录；团队页能否看到结论、阻塞与下一步；文书能否扫读并回到原文。Agent 席用原 ID 检查同一条内容。前端席检查键盘焦点、手机阅读、空结果、错误重试和旧入口。每次评审记录可复现的障碍与修正，迭代以实际使用反馈为依据。
