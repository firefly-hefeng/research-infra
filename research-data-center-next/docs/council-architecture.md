# 公共区数据管理中心：架构议会综合评审

本评审以用户最新确认的范围为准：“公共”指服务器公共区，完整整理 `/data/datasets` 与 `/data/models` 中的全部资料。公共区位置不等于开放版权、不等于所有成员可读，也不等于允许对外分发。本文替代此前更宽资产盘点及临时窄名单建议；目录数量以当前 `/api/summary` 的实际范围、时间与统计为准，不在计划中固定数字。

议会是架构、科研、数据运营与安全四个分析视角，不代表多个真人专家或外部机构认证。当前重点是低影响、原位、只读编目；新接入、上传、正式发布和内容分发属于后续建设计划。

## 1. 已确定的范围与行为边界

- 整理目标为两公共根的全部内容，包含数据集、模型、标签、特征、集合、配置、说明和其他公共资料。不能根据目录名、用途、混合许可或是否开源筛掉公共区内容。
- 公共根之外的成员家目录、项目目录和实验输出不纳入；不跟随符号链接越过两个公共根边界。内部别名链接需要记录关系并防止重复计数。
- 三台服务器分别核对公共根映射、访问方式和采集范围。另一主机没有实连，不等于路径缺失，也不能宣称已完成本轮核验。
- 公共区的不可读入口可记录为 `restricted`。它表明当前账户的访问限制，不改变条目属于公共区的事实。不得提权读取、自动 chmod 或改变原权限；不可读内容不能由本系统分发。
- 不移动原文件，不改变目录名称，不修改成员训练、业务服务或运行环境。平台独立部署在 `/data/rmp/research-data-center`。
- 不全盘扫描，不解码原始内容，不运行模型，不重新提取特征。公共区全覆盖是整理目标，当前完成度必须由入口、深度、批次、错误和剩余范围证明；不能将目标范围写成已验证范围。
- 日常更新使用低 I/O stat 和已知目录清单差异；初次目录映射在两个根内分批进行，限制并发、时间与扫描预算，可暂停。

## 2. 当前能力与后续能力

当前采用单体服务与 SQLite 本地持久化目录，支持检索、筛选、详情、元数据 JSON/CSV 导出、只读资料 API、OpenAPI 与 Agent 使用清单。HTTP 资料接口不上传、下载、移动或修改原始内容；数据库查询以只读模式打开。

服务监听 `127.0.0.1:8765`，经 SSH 隧道访问，默认无公网。单一管理员令牌保护资料 API 和文档；浏览器通过 `POST /api/session` 建立 HttpOnly、SameSite Strict 会话，Agent 使用 Bearer 令牌。服务端令牌存储于权限为 `0600` 的 `var/access-token`，不进入源码。该机制不是个人身份系统，也没有完整 RBAC，成员多角色与范围化凭据属于下一阶段。

尚未实现的能力包括：成员接入审批、CLI/SFTP/rsync 会话与容量预约、服务器侧原位登记 API、正式版本发布、内容冻结、实验引用、只读内容分发、配额和自动回收。网页上传只作为未来可选的小文件或说明附件入口，不作为服务器大文件接入的前提。

## 3. 四个评审角度的共同结论

| 角度 | 建议 | 对实施的约束 |
| --- | --- | --- |
| 架构 | 保持 SQLite 单体，资源身份与实际位置分离 | 暂不做大批复制、存储迁移、微服务或向量检索 |
| 科研 | 帮助找到输入、理解版本和保存引用 | 不接管成员工作区；保留训练路径和原使用方式 |
| 数据运营 | 每项公共资料有维护人，未知信息有待办 | 先完整编目，再补用途、来源、许可、版本和关系；不能因未知漏掉条目 |
| 安全 | 公共位置、元数据可见、当前内容可读、允许分发分别判断 | 不以系统权限代替资料使用授权；元数据导出也遵守共享范围 |

下一步优先确定负责人、公共区目录映射和元数据共享边界，而不是大批复制资料。来源或许可未明的公共区条目可先编目，但不能据此开放内容分发。

## 4. 通用数据模型

一期保留现有条目与来源快照；后续逐步规范实体，不需要先建立复杂科研本体。

| 实体 | 核心信息 | 关键约束 |
| --- | --- | --- |
| Resource | 稳定 ID、名称、类型、简介、维护人、任务与格式 | dataset/model 为主要类型，允许特征、标签、集合等必要类型；未知类型保留待整理 |
| Release | 资源 ID、本地版本、上游 revision、状态、时间、清单摘要 | 上游版本与本地整理版本分列，不覆盖已发布版本 |
| Artifact | 相对路径、用途、格式、大小、摘要与校验范围 | 文件数量、样本数量和目录条目数量分开，未知不写成零 |
| Location | 主机 ID、公共根 ID、相对路径、当前可读性、核验方法与时间 | 先验证路径边界；不能以一个副本的可读性推断其他位置 |
| Evidence | 来源 URL 或维护方、定位、来源时间、声明、获取方式 | 文档记载、文件属性观测和人工确认分开，冲突保留依据 |
| License | 许可证或许可依据、适用版本、使用条件、再分发限制 | 公共区位置不是许可；混合许可或未知如实标注 |
| Relation | 起止版本、附件/派生/微调/训练/评测关系、处理依据 | 同名或相邻目录不等于已证实关系 |
| Policy | 元数据共享范围、内容使用范围、分发范围、维护权限 | “可见”“可读”“可分发”不能合并成一个布尔值 |

目录记录与逻辑资源分开。一个数据集的原件、标签和特征可能对应多个目录；一个目录也可能包含多项资源。聚合规则与原始路径对应关系应可解释，不以自动猜测覆盖原始证据。

目录统计需显示当前采集范围、时间和未完成项。父子目录、别名、同源版本或副本存在重叠，不能把条目容量直接加成服务器占用；文件系统实际可用空间是单独的运行指标。

## 5. 目录约定与完整整理流程

既有资料只做原位登记，保持原目录和权限。新发布资源可采用 `datasets/<slug>/<version>/`、`models/<slug>/<revision>/`，配套说明、许可证与文件清单；实际发布根由公共区维护方批准。该约定不要求迁移或重命名已有内容。

整理流程分为：

1. 对两个公共根建立主机与根目录映射，记录边界、可读性和更新批次。
2. 分批获取入口与有限清单，标注实际深度、失败、权限限制和剩余范围。
3. 保存原位置、名称与来源依据，按类型和用途整理逻辑资源；未知类型和未知来源继续保留待办。
4. 由维护人补充简介、任务、格式、版本、官方来源或资料责任方、许可证和使用方式。
5. 对重复候选、原始/派生关系和版本冲突进行人工核对；不直接删文件、替换硬链接或物理去重。
6. 发布目录快照，检查搜索、详情、API 与导出一致；后续按变更低成本更新。

一期以经过验证的目录快照事务化导入 SQLite。后续应用写入上线时保持单一权威维护入口，JSON/CSV 和资源说明作为导出或交换材料，不做数据库与文件相互覆盖的双向编辑。

## 6. 科研流程与版本保证

使用者先按任务、模态、格式、来源和许可寻找公共输入，确认当前可读性，再按原路径或未来只读分发方式获取。成员实验输出仍在原工作区；有意贡献到公共区时由成员主动提交，不由管理服务自动抓取。

版本状态至少区分：

- `observed`：记录某时刻可观察的入口与文件属性，附独立可读性结果。路径存在或 stat 成功不表示内容完整。
- `manifest_pinned`：清单与相应内容摘要固定，可以检查漂移；源位置可能仍被修改，清单本身不能恢复旧内容。
- `content_frozen`：内容处于明确管理的不可覆盖位置，具有可验证清单、写入约束和恢复安排。

XFS 并不自动代表已有快照能力；普通硬链接也不能抵御源文件原地修改。不能通过修改他人原目录权限来冻结版本。完整摘要只对确需发布或复现的版本，在明确 I/O 预算与低负载窗口执行，可暂停；校验范围要写清。

实验引用保存资源 ID、版本 ID、实际文件或子集、清单摘要、上游模型 revision、处理代码 revision、配置与运行时间。`latest` 或一个可变目录字符串不足以证明实际输入。发现漂移时标记需复核并保留旧证据，不静默改写历史。

## 7. 接入方式：服务器侧暂存与原位登记为主

二期提供两个主要模式：

- `register`：登记已在两公共根中的资料。提交 `root_id + relative_path`，核对边界后仅写元数据。说明、来源或许可证缺失可标记待补充；权限不足保留 restricted，不复制、不改权限、不移动原文件。
- `transfer`：成员主动提交新的公共资料。创建接入会话和容量预约后，用 CLI/SFTP/rsync 写入本系统专属暂存，再进行完整性检查、说明补齐、许可确认和正式发布。服务不读取成员项目目录作为隐式上传来源。

建议暂存位置为本项目 `var/ingest/<ingest_id>/` 或批准的同文件系统目录，按提交者隔离。已有 SSH/SFTP/rsync 工具负责大文件传输与断点续传；管理接口负责状态、容量、元数据、审核和发布。网页只可选支持小文件，不为大文件重新发明浏览器传输链路。

| 拟定 API | 用途 | 核心约束 |
| --- | --- | --- |
| `POST /api/v1/ingests` | 建立 register 或 transfer 会话 | 鉴权、幂等键、模式和路径边界；新内容需要责任人及容量预约 |
| `GET /api/v1/ingests/{id}` | 查询状态、登记结果或暂存说明 | 仅提交者和授权维护人可见，不授予任意目录访问 |
| `POST /api/v1/ingests/{id}/complete` | 提交清单并声明传输完成 | 校验数量、大小、路径；拟冻结内容完成最终摘要检查 |
| `PATCH /api/v1/ingests/{id}/metadata` | 整理说明、用途、来源、许可、版本与关系 | 不得通过改描述绕过内容许可或扩大发布范围 |
| `POST /api/v1/ingests/{id}/publish` | 发布资源、版本与只读位置 | 审核与校验通过；不覆盖已有版本；原位模式只发布元数据 |
| `DELETE /api/v1/ingests/{id}` | 取消并回收该会话专有暂存 | 不删除原位来源、已有公共资源或成员文件 |

状态流建议为 `requested → admitted → receiving/registered → validating → ready → publishing → published`。缺说明进入 `needs_metadata`，另有拒绝、取消和过期状态。流程结束不自动提高内容保证级别；原位记录仍可保持 observed。

所有文件路径使用受控根和规范化相对路径，拒绝越界、重复规范化路径、特殊文件与越界符号链接。压缩包不默认解包；若未来支持，单独检查展开路径和容量。未知脚本或模型对象不执行、不反序列化。

新暂存与发布目标同盘时可用验证后的原子重命名减少复制。文件重命名和数据库事务不是同一原子操作，需要持久化发布记录、重启对账和可恢复状态；publishing 不出现在正式可用列表中。原位模式不做文件切换。

## 8. 内容权限与只读分发

公共区全部资料进入整理范围，不表示原始内容全部可以读取或再分发。restricted 是当前账户限制；来源许可未知、带条件或混合许可，应明确写出，避免默认为开放资源。

未来分发优先提供授权的原位引用、版本清单和只读内容流。内容接口只接受已登记资源/文件 ID，后端解析公共根内位置并检查当前权限与许可。不能允许调用者提交任意绝对路径，也不能通过打包、样本或外部 Agent 输入绕过限制。

同一套范围判断覆盖搜索、详情、统计、导出和内容接口。元数据也不默认上公网；当前仍通过管理员凭据与 SSH 隧道访问。向成员开放接入时增加个人身份、独立可撤销服务凭据和角色，不能用共用服务器密码代替应用身份。

跨机内容复制需要记录目标位置、接收范围、用途、容量、责任人与有效期。尽量流式传输，不预生成整库压缩副本；若许可或空间不足，保留元数据和定位引用即可。

## 9. 存储容量、回收与恢复

`/data` 已确认为本地 XFS。当前容量以实际采样或 `/api/summary` 的已有范围信息为准；计划不固定剩余容量数值。元数据目录不等于原始资料的第二份副本，原位登记优先。

以下为初始建议阈值，尚未实施，应按精确字节、增长趋势和运行预留确认；百分比或绝对空间任一触发即从严处理：

| 状态 | 建议条件 | 行为 |
| --- | --- | --- |
| 提醒 | 使用率达到 85% | 跟踪增长，检查暂存、缓存和分发副本，新内容预估容量 |
| 限制新增 | 使用率达到 90%，或可用空间低于 750 GiB | 暂停新批量传输与复制；保留查询和低成本原位登记 |
| 紧急保护 | 使用率达到 95%，或可用空间低于 500 GiB | 停止非必要内容写入，保障目录、服务和恢复预留 |

接入准入扣除最低运行预留与尚未写入的其他有效预约，已落盘暂存不重复扣减。预约要事务化，实际传输再次检查空间。SFTP/rsync 接收必须配合可执行的配额或受控落盘位置，不能只在会话创建时检查容量。

回收对象只限本系统新建的暂存、失败残留、缓存和临时分发副本。建议暂存空闲 48 小时进入到期处理、最长保留 7 天，待实际传输规模确认；清理核对会话状态和专属目录，释放预约并留记录。原位来源、既有公共资源、成员文件和被实验引用的唯一正式副本不自动删除。

目录备份包括 SQLite 一致快照、公共范围证据、配置与代码版本，建议每日及变更后执行。区分同盘回滚副本与独立故障域备份；历史非公开证据与备份不进入发布目录或文档接口。

原始内容恢复独立规划：确认上游可重新获取性、版本保留、许可与备份位置。导出 JSON 不能恢复数据文件或权重。目录恢复建议目标为最多丢失 24 小时元数据变更、4 小时内恢复查询，需维护人确认并通过干净环境恢复演练后承诺。

## 10. 推进顺序、责任与验收

P0：数据运营与资源维护人完成两公共根的目录映射、负责人认领、用途与元数据共享边界；平台运维确定低 I/O 更新预算、容量预留和备份恢复基线。公共口径已确定，不再等待“是否开源”决定已有公共区条目是否入目录。

P1：平台开发与维护人建立个人身份和成员角色，先用一组公共资料试行原位登记与服务器侧暂存。新内容发布有责任人、来源和许可说明；未知信息的旧公共资料继续编目并列待办。

P2：有实际需求后建设只读分发、实验引用与多机目录联动。不会为了管理统一而自动复制所有公共资源。

一期验收要求：

- 范围按两公共根位置定义，不按目录名、用途或开放许可误筛；成员目录和越界符号链接不混入。
- 页面、搜索、详情、API、导出和发布文档范围一致；历史公共区外记录不重新进入结果。
- 当前摘要准确给出实际采集入口、深度、时间、失败和未完成范围；条目数不冒充独立数据集数。
- 公共区的 restricted 如实保留，不提权、不自动改权限、不据此提供原始内容。
- 路径核验不标作内容完整性验证；未知计数不填零，重叠容量不直接加总。
- 更新低 I/O、可暂停，原文件、权限、训练任务和既有服务保持原状。
- 令牌、只读数据库、失败导入回滚、重启持久化和公共目录恢复得到验证。

二期开通要求：

- 原位登记不搬文件，服务器侧传输可恢复，不依赖网页上传。
- 容量预约、配额、实时空间保护、取消和到期回收均有效。
- 路径边界、会话隔离、校验失败、传输中断和发布中断有确定结果，不产生半发布内容。
- 版本不可覆盖，清理不能触及原位来源；分发同时满足实际权限与许可条件。
- 个人身份、责任人、来源、许可、状态变更与发布记录可追溯。
- 一次完整接入试点和一次恢复演练通过后再扩大参与范围。

## 11. 未决事实

1. 各公共区资料由谁维护；用途、来源、许可证及元数据共享边界哪些尚未补齐。
2. 两公共根的实际结构、分批采集预算、更新周期和权限受限时由维护人补充的方式。
3. 其他主机的公共根映射、适当访问方式与可验证范围，不沿用历史全资产覆盖率。
4. 新接入采用哪些用户账户、暂存根、配额与发布角色，典型文件大小和网络情况怎样。
5. 哪些版本需要内容冻结、长期保留或上游镜像，现有备份与恢复能力是否满足需求。
6. 谁负责执行容量处置、到期回收和恢复演练，如何留下可追溯的运行记录。

这些问题影响实施细节，不改变已确定的公共区全覆盖目标和不干扰成员运行的边界。
