02

四个角度，一条共同边界

公共资源优先，成员运行优先

“议会”表示架构、科研、数据运营和安全四种分析视角，不表示多个真人专家或外部认证。共同结论是：完整整理两公共根内的资料，减少重复寻找和下载；边界外的成员工作区不纳入。

A / 架构

单体与原位索引

SQLite 与只读 API 足够支持当前目录。将资源、版本和实际位置分开，既有公共资料不因建目录而移动。

暂缓：大批复制、存储迁移、全盘检索。

B / 科研

可判断、可引用

记录任务、格式、来源、上游版本与使用条件，让研究者选择输入；版本清单和实验引用随后逐步完善。

保持：训练路径、文件、权限与运行方式。

C / 数据运营

每份公共资料有人管

维护人补齐用途、来源和许可证，整理重复候选、别名、版本和说明；信息不全先明确标记，不因未知而漏掉公共区资料。

下一步：负责人、目录映射、元数据质量。

D / 安全

目录收录不授予内容权限

公共区位置、当前账户可读性、许可使用与再分发范围分别记录。元数据可展示不意味着可以打开、下载或改变源内容。

排除：公共根外的成员目录与越界符号链接。

不干扰成员与既有服务

不修改原数据权限、文件和训练任务，不扫描公共根之外的成员家目录或项目目录。公共根内部即便包含混合许可、研究集合或业务用途资料，也先按位置完整编目，再独立标注用途与限制。三台服务器分别核对公共根边界；其他主机未核验的记录不能宣称本次已检查。

03

以准入与验收推进，不预设日期

分期路线

  1. 一期当前基线

    公共区全部资料的只读目录

    按两公共根边界编目，以低 I/O、分批元信息核验逐步完善覆盖；提供搜索、详情、元数据导出和 Agent 查询。

    基线要求：按位置纳入全部公共资料，排除公共根外目录和越界链接；实际覆盖范围、缺口与错误明确，不宣称内容完整验证。

  2. 一期完善下一优先

    负责人认领、完整目录映射与说明

    公共区口径已经确定；下一步补齐每台主机的公共根映射、维护人、来源、许可证、版本和用途，明确元数据共享及内容使用边界。

    进入二期：责任角色、身份方式、新内容发布规则、存储预留和备份责任明确；选一组资料试点。

  3. 二期待实现

    服务器侧接入、整理与发布

    既有公共资料通过原位登记进入目录；新资料由 CLI / SFTP / rsync 进入专有暂存，完成来源、许可和完整性检查后发布。

    开放要求：身份、容量预约、路径边界、断点续传、失败恢复、版本不可覆盖与暂存回收通过验收。

  4. 三期按需推进

    版本引用、只读分发与多机公共目录

    提供版本清单、实验输入引用和按许可的只读获取；跨机复用优先共享引用，确需复制时记录位置、责任人和有效期。

    扩展要求：另一主机的公共范围另行准入，容量和分发需求有证据，权限与恢复方式经验证。

既有资源：原位登记

保留原路径和权限，登记稳定 ID、位置、来源与维护人。位置须在两公共根内；本机不可读的公共资料保留受限状态，不能通过提权或改权限补齐内容。无来源说明不等于从目录排除。

新资源：规范目录

建议新发布资料采用 datasets/<slug>/<version>/ 或 models/<slug>/<revision>/，附说明、许可证与清单。实际发布根由维护方批准；这一约定不要求改名或迁移已有资料。

一期由审阅后的公共目录快照事务化导入 SQLite，查询接口只读。二期应用写入上线后，应选定单一权威维护入口，JSON/CSV 和资源说明作为导出或交换结果，避免数据库与文件互相覆盖。

06

公共目录不等于公网服务

共享边界与只读分发

当前单一管理员令牌，不是完整角色权限系统

资料 API 与文档受令牌保护，服务仍仅绑定回环地址。浏览器通过 POST /api/session 建立 HttpOnly、SameSite Strict 会话；Agent 使用 Bearer 令牌。服务端令牌保存在 0600 的 var/access-token，不进入源码。后续向成员开放接入时再建立个人身份、可撤销服务凭据与团队角色。

01

元数据可共享

名称、说明、来源、路径、统计和导出属于同一批准范围。公共根之外的成员资料完全排除，不能仅改成 restricted 后展示。

02

当前内容可读

公共区位置、来源许可和 Unix 可读性分列；区内资源也可能 restricted。权限不足不分发、不提权、不自动 chmod。

03

内容可再分发

另行确认许可证和接收范围。能够读取或进入公共目录，都不自动授权公网下载或对外镜像。

未来分发只提供已准入资源的只读路径、清单或获准内容流。文件接口接受资源/文件 ID，由后端解析批准位置，不接受任意绝对路径。跨主机复制需要目标主机的准入、许可和容量检查；尽量避免预生成整库压缩包。

07

二期设计 · 不要求从网页传大文件

服务器侧接入与发布

A · 已有公共资料原位登记

提交两公共根内的 root_id + relative_path 与已有说明；来源、许可证或维护人缺失时标记待补充。服务核对路径边界，建立目录记录，不复制、不改变文件或权限。

B · 新资料进入专有暂存

先申请接入会话和容量预约，再以 CLI / SFTP / rsync 传入分配的暂存位置。传输工具负责断点续传，接入服务负责状态、校验、整理和发布。成员主动提交，不由服务抓取其项目目录。

建议暂存位于本项目专有的 var/ingest/<ingest_id>/ 或另行批准的同文件系统目录，按提交者隔离。接收时声明大小与文件清单；正式发布到批准公共根前，确认来源、许可证、共享范围和维护责任。网页仅作为可选的小文件与说明附件入口。

  1. requested申报资料与模式
  2. admitted准入与容量预约
  3. receiving / registered暂存接收或原位登记
  4. validating清单与完整性检查
  5. ready来源与元数据齐备
  6. publishing版本发布与对账
  7. published只读资源可检索

信息不足进入 needs_metadata；失败、取消、过期分别记录。原位登记的内容校验级别可保留 observed，不能因流程结束就标记内容冻结。仅新暂存内容可依会话规则清理。

拟定接入 API；当前尚未实现，不是现有只读接口
接口用途关键约束
POST/api/v1/ingests申请 register 原位登记或 transfer 暂存接入。身份、幂等键、路径边界与模式；新内容需容量预约和责任人，原位登记允许来源字段待补充。
GET/api/v1/ingests/{id}返回状态、暂存接收说明或登记结果。只对提交者和获授权维护人可见；不授予任意目录访问。
POST/api/v1/ingests/{id}/complete提交清单，声明服务器侧传输完成。校验文件数量、大小、批准范围；拟冻结发布的内容需验证最终摘要。
PATCH/api/v1/ingests/{id}/metadata补充说明、格式、来源、许可、版本关系与维护人。不能用修改元数据绕过公共准入或扩大再分发权。
POST/api/v1/ingests/{id}/publish发布资源/版本与只读位置。审批与校验均通过；不覆盖已有版本；原位模式不移动源文件。
DELETE/api/v1/ingests/{id}取消接入，回收本会话专有暂存并释放预约。不删除原位登记来源、既有公共资源或成员文件。

接收与整理

相对路径拒绝越界、重名冲突、特殊文件和越界符号链接；压缩包不默认展开。重复摘要只提示复用，不自动删除或合并。整理优先补充说明、版本和清单，不做未经请求的格式转换。

可靠发布

新暂存与目标同盘时用验证后的原子重命名减少复制。文件切换与数据库事务分别记录，重启后能够对账；原位模式只发布元数据。正式版本不得被后来上传覆盖。

08

避免为整理制造第二份大数据

容量、回收与备份恢复

现状以当前摘要和运行采样为准

/data 是本地 XFS。容量使用、可用空间与更新时间请查看 当前摘要 中已有的范围信息；摘要未提供的运行指标标记待采样。目录容量存在重叠时不求和，不把全部剩余空间承诺给接入会话。

建议阈值，尚未启用；需按精确字节、增长与预留确认
状态建议触发条件行为
提醒使用率 ≥ 85%查看增长、暂存与缓存；新内容先做容量预估。
限制新增内容使用率 ≥ 90%，或可用 < 750 GiB暂停新批量传输、导入复制和分发包；低成本原位登记与查询继续。
紧急保护使用率 ≥ 95%，或可用 < 500 GiB停止非必要内容写入，保障服务与恢复预留，通知维护人。

准入应扣除最低运行预留和其他尚未写入的有效预约，已落盘暂存不重复扣减。并发预约使用事务；实际传输仍检查空间变化。SFTP/rsync 接收端需配额或受控落盘位置，不能只在创建会话时检查一次就放任写满磁盘。

回收只覆盖本系统工作副本

新接入暂存、失败残留、缓存和临时分发副本有责任人与到期时间。建议空闲 48 小时进入到期处理、最长 7 天；最终时限由实际传输量和网络情况确认。

清理先核对会话状态和专属目录，释放预约并留记录。既有公共来源、成员资料、原位登记内容和仍被引用的唯一正式副本不自动删除。

元数据与原始内容分别备份

目录备份包括 SQLite 一致快照、公共范围证据、配置与代码版本。建议每日及变更后执行；本机回滚副本与独立故障域备份分别安排。

原始公共内容的恢复另行确认：上游是否可重新获取、版本是否保留、许可是否允许镜像。导出 JSON 不能恢复模型权重或数据文件。

目录恢复建议目标为最多丢失 24 小时元数据变更、4 小时内恢复查询，需由运维确认并演练后承诺。使用干净目录恢复，核对批准范围、关键字段、条目数和鉴权。历史非公开证据与备份不进入公共发布目录或文档接口。

09

低影响更新，证据充分才扩大范围

运维与验收

完整覆盖目标通过两公共根内的分批目录映射实现，记录每批入口、深度、时间、失败和剩余范围。使用普通账户，限制并发、超时和 I/O；日常以 stat 与已知清单差异为主。禁止全盘扫描、遍历边界外成员工作区、改权限、搬文件或改变训练与业务服务。

一期范围验收

当前基线
  • 以两公共根全部内容为整理目标，不按目录名、用途或开放许可误筛。
  • 页面、API、导出与文档范围一致；公共根外成员目录及越界链接不混入。
  • 主机、采集入口、深度、时间、失败和剩余覆盖缺口明确。
  • restricted 仅说明当前访问限制；不改权限、不据此漏掉公共区记录。
  • 路径核验不标作内容完整验证；数量从当前摘要获取，失败导入可回滚。
  • 鉴权、只读与恢复可验证；低 I/O 更新不改变成员任务、文件或服务。

二期开通门槛

后续验收
  • 新内容有提交者、维护人、来源与许可依据；原位未知字段保留待补充。
  • 原位登记不搬文件；服务器侧传输可恢复，不依赖网页上传。
  • 容量预约、配额、实时空间保护与暂存到期清理有效。
  • 校验失败、取消、断线与发布中断有确定结果，无半发布版本。
  • 发布不可覆盖，取消不触碰原来源；分发符合许可和实际权限。
  • 一次公共目录恢复与一种新资源接入试点通过记录化验收。
运行交接材料

维护人和角色、允许清单维护方式、启动停止、SSH 隧道访问、凭据轮换、低影响更新、备份恢复、容量阈值和失败回退说明。凭据不进入源码、目录导出或日志。

扫描失败保留上次已知状态并标记时间和原因，不把失败空结果当作资源全部消失。退出准入范围的条目从发布视图移除，其原内容保持不动。

待决事项与依据

  1. 如何分批完成公共区目录映射？范围已确定为两公共根全部内容；待确定批次预算、更新周期和权限不足时的维护人补充方式。

  3. 三台主机的公共根如何核验？逐机确认同类公共边界与访问方式；其他主机未实连时保留未核验状态。
  4. 成员接入如何落盘？确定独立账户、暂存根、配额、发布权限与预计文件规模；不把网页传输作为前提。
  5. 哪些内容需要冻结或保留副本？依据上游稳定性、实验引用和存储空间决定；不默认复制全部公共资料。
  6. 备份和回收由谁执行？确认故障域、保留周期、恢复目标与暂存清理规则，先演练后承诺。
