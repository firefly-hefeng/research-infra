# 议会意见：公共资料目录的实现与运维审查

评审时间：2026-10-19（北京时间）。角色为 **AI 实现 / 运维审查**，不是现实中的真人专家会议。本角色实现了目录 API，并审阅另一实现角色编写的采集、规范化与部署流程。

## 当前硬边界

以用户最终明确的范围为准：**纳入 `/data/datasets` 与 `/data/models` 两处公共区的全部内容，不按版权、开源程度或业务用途过滤，不干扰成员正在运行的任务**。这里“公共区”是服务器存放位置，并非许可证或访问权限判断。后续计划围绕公共数据库整理和上传接口；前端上传页面不是当前需求。

此前包含其他目录观察记录的范围和统计已撤回，不作为当前目录、前端、导出或验收依据。本报告不展示个人项目路径或其数据统计。尚未按新范围完成复核的旧快照不得启动服务或混入新目录。

当前实现必须满足以下约束：

- 公共根固定为 `/data/datasets` 与 `/data/models`，两根之下所有内容均属编目范围；使用逐路径组件判断，拒绝目录同名前缀、`..` 越界和跨界符号链接。
- 不以研究方向、业务用途、许可证未知或当前 rmp 不可读为排除理由。域外成员工作区不扫描、不发布；公共区派生物也保留，并在 dataset 的 subtype 中标注原分类。
- 只采集目录和文件元数据及受限配置字段。不得加载权重、推理、执行配置、读取逐条样本、生成特征或全盘哈希。
- 维护操作不移动原始内容、不改变源权限、不停止成员进程、不重启训练服务。目录服务只读运行，低优先级和明确的扫描预算用于减少 I/O 干扰。
- 目录 JSON、SQLite、构建报告、前端、API、导出和文档必须遵守上述两根范围；鉴权不改变内容是否在范围内的判断。

## 本轮已落实的实现保护

| 项目 | 已确认措施 | 验收限制 |
| --- | --- | --- |
| 配置内容读取边界 | 配置目标限制在两处公共根内；`O_NOFOLLOW` / `O_NONBLOCK` 打开后再次核对 `/proc/self/fd` 真实目标；`fstat` 拒绝非普通文件及过大文件；最多读取 200001 字节 | 合法公共区内链接可核验；跨界链接不得跟随。 |
| 元数据查询与导出 | 在线 SQLite 连接使用 `mode=ro`；资产内容按文本处理；JSON/CSV 只导出已导入的目录元数据 | 已按新公共区回执及过滤 CSV 重建，不随包发布原始混合台账。 |
| 导入一致性 | 全量校验后事务替换；重复 ID 或非法记录整体失败；保留 unknown 与真实零值区别 | 应在允许列表验证通过后才执行正式导入。 |
| 访问保护 | 回环监听、Bearer 令牌、HttpOnly 浏览器会话、同源检查和受限静态路由 | 这是附加防护，不构成将非公共条目纳入目录的授权。 |
| 备份命令 | README 使用绝对源路径与 SQLite `mode=ro`；不存在的源不会被意外创建为空库 | 新范围上线前，应明确旧回滚副本不得被误当成当前公开目录恢复。 |
| 不完整统计 | 文件 stat 失败或目录截断时大小为 null，记录错误；采集缺口传播至 scope、sources 与构建报告 | 新公共目录仍需核对未知值和截断提示，不将路径条数表述为独立数据集数。 |
| 扫描负载 | 单目录条目数有上限，权限探测有超时，内部有目录数和时间预算 | 120 秒仍是内部软预算；应使用外层超时和低 I/O 优先级，只有新增公共根才需要扫描。 |

## 新范围必须完成的验收

1. **范围固定。** 两处根入口均明确列入 scope 和来源定位。根内全部内容纳入，根外拒绝，不新增按开源、许可证或用途审批的筛选步骤。
2. **入口和符号链接双重检查。** `config.paths`、`model_roots`、每个扫描目录和被读取配置的真实目标均需落在允许范围。根外链接不得跟随；合法缓存链接只允许落在批准的公共缓存范围内。
3. **来源证据分离。** 发布用 `public-assets-20261018.csv` 仅含阿里云公共区行、字段白名单，并清除文本字段中的域外路径；混合原 CSV / ZIP 不随发布。原 CSV 缺失时可仅用发布 CSV 和 `live-public-metadata.json` 重建。许可未知独立记录，不影响纳入。
4. **测试不存在的边界。** 在临时目录中构造一个允许根和一个根外目录；对拒绝的目录断言没有执行 `scandir`、打开配置或导入记录。测试不得扫描真实个人资料。
5. **数据层对齐。** 前端、API summary、搜索、详情、JSON/CSV 导出、Agent manifest、构建报告中只出现当前公共目录条目。旧数量和旧路径不能残留在演示数据、详情缓存、文案或包内附件中。
6. **非干扰验证。** 运行前后只观察新进程自身的资源占用；使用低优先级、限额和一次性增量核验，不为验证非干扰而枚举成员训练进程或其他目录。
7. **部署只新增本服务。** 使用确认可运行的较新 Python，以受限账户启动回环目录服务；不修改已有训练服务。首次安装说明包括项目权限、令牌权限、导入、单元安装和健康检查。

## 保留的实现改进项

- 目录项 `is_file/is_dir` 异常、非对象 JSON 配置和结构异常的配置字段应按条目隔离，不能使一次公共目录更新全部中断。
- 本次重写已将访问状态只依据路径核验，历史“空下载”保留在原始语义字段，不能覆盖当前缺失或权限结论。
- 来源记录数由实际输入计算；更换公开来源或快照日期时，同时更新来源标识及证据日期。
- 备份采用时间戳、完整性检查和恢复演练；回滚操作也要检查当前公开允许列表，防止恢复过期范围。
- CLI 可补齐后端已有的 category 筛选。更大目录下再测量导出内存和并发容量；当前不需要引入额外数据库、训练任务或 GPU 依赖。

## 验证记录

新增 `tests/test_collection.py`，仅在临时目录测试根内普通 JSON、根内链接、根外链接、过大文件、目录与 FIFO。另有 `tests/test_public_catalog.py` 验证公共根、目录同名前缀、`..` 越界、跨界链接、仅发布 CSV 重建，以及 SQLite JSON/CSV 导出不泄漏域外路径。相关测试全部使用合成资料，不接触真实个人数据。

当前构建为 **228 条目录记录**：198 条台账记录对应 191 个公共路径，新增 7 个权重入口和 23 个未覆盖最浅目录集合。主分类为 dataset 218 条、model 10 条（其中 3 条是模型区集合）；restricted 199 条、verified 29 条。这不是独立数据集、样本或可运行模型数量。大量已发现子目录通过台账或最浅集合入口代表，不逐个制造新的资源计数。两根下未细分内容仍属范围，但没有宣称完成逐文件扫描。

Windows 本地新增 3 项范围测试已通过；原 15 项后端测试通过，6 项 Linux 专用测试因平台跳过。Linux 实跑结果由服务器验收补充，跳过不计为通过。

未发现当前标准库 API 对 Python 3.14 或 SQLite 的确定性兼容阻断。systemd 文件本身不能证明服务已启动或新范围已验收。本轮审查将公共根允许列表、新来源重建以及不干扰现有任务作为上线前置条件；此前旧范围的导入成功不再作为当前交付的成功证据。
