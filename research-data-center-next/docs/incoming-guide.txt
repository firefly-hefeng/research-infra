资料增补：放好文件，写几句说明

使用者只需准备资料和 README。数据集、模型的正式说明、资源身份、版本和入库审核由管理团队维护。

1. 放到本人的增补目录

/data/share/incoming/<用户名>/<提交名>/
├── payload/       资料文件，保留清楚的内部结构
└── README.md      五项简短说明

使用管理员已开通的本人目录，每次提交新建一个名称，例如 20261028-example-audio。文件可以通过已有的服务器传输方式放入，不必经过网页。不要直接写正式数据集或模型库。本人目录缺失、权限不对时联系管理员。

2. README 写五项即可

名称：这份资料叫什么
来源：下载链接、采集方式或生成过程
用途：准备研究什么问题
内容：有哪些文件、主要格式和大致规模
使用限制：许可、团队使用条件；不清楚就写“未知”

下载 可直接填写的 README。不要求使用者填完整数据卡、JSON、文件哈希或发布版本。不知道的信息如实注明，不从目录名称猜测。

3. 上传完成后交给管理员

确认所有文件传输完毕、下载与写入程序已经退出，在 README 末尾单独添加一行：

传输完成

此后停止修改，把提交路径发给管理员接手。这个标记只是你的交接声明，不会自动发布，也不表示已经进入后台队列。

4. 后续由管理团队处理

管理员检查内容、权限与说明，联系你补充必要信息，生成协议清单，再确定整理位置、正式说明和发布版本。已有规则工具继续服务这一管理流程，用户无需操作后台命令。

如果需要更正或撤回，先联系管理员；不要在交接后继续覆盖原目录。大规模下载、批量整理或空间不足先另行讨论。三机同名账户与权限仍需逐机核对，公共目录也不代表资料可以对外分发。
