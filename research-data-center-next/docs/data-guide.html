01

找到适合研究的资料

在数据管理按研究方向、关键词或资源类型查找，先读用途、来源、内容、使用限制和实际路径。记录数、文件数与研究样本数含义不同；集合入口也不一定是一份独立数据集。标为“可读”只说明入口检查通过，使用前仍应核对划分与必要文件。

正式资料位于 /data/share/datasets 和 /data/share/models。优先使用说明中明确的版本；旧资料尚无冻结版本时，记录资源 ID、实际路径和观察日期，不自行补造版本号。

02

在自己的目录开展实验

公共库作为输入读取。代码、环境、缓存、检查点和实验输出放在自己获准使用的工作目录，不写回正式库。记录输入资源、版本或路径、训练测试划分、代码版本、参数和主要结果，便于复现。发现缺文件、说明错误或重复资料时反馈给管理员，不直接删除、重命名或合并。

03

增补只需文件和 README

在管理员已开通的本人目录中，每次新建一个清楚的提交名：

/data/share/incoming/<用户名>/<提交名>/
├── payload/       本次资料
└── README.md      简短说明

README 写五项：名称、来源、用途、内容、使用限制。来源尽量提供链接或采集方式；内容说明格式及大致规模；不知道的明确写“未知”。不要为了填表猜测许可、样本数或来源。可下载 README 模板。

全部传输完成、写入程序退出后，在 README 末尾单独写一行“传输完成”，随后停止修改，并把提交路径交给管理员。未完成的上传不要写此标记。

04

交给管理员整理

管理员检查文件与说明，必要时联系你补充，再生成协议清单、确定资源身份与版本、审核入库。写了“传输完成”不等于已入队或已发布；用户不需要制作 JSON、哈希或完整数据卡。

更正请联系管理员，或用新提交名说明与旧提交的关系。特别大的下载、整理或批量搬运先协调容量与时段。三机共享盘的同名账户权限仍需逐机确认；入口缺失时联系管理员，不自行扩权。
