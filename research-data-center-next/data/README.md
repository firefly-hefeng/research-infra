# 数据与模型共读说明

从平台「数据与模型」找资料，先选研究大类和细分类，再读卡片中的用途、范围与来源。数据目录、模型权重、候选线索和实验整理都沿用各自的角色。原始表与正式资料的使用条件由资料负责人或提供方确认。

| 要改的内容 | 编辑位置 |
| --- | --- |
| 研究大类、细分类、获取进展 | 飞书「公司数据与申请台账」对应行。按 `library-taxonomy.json` 的中文层级选择，保留行 ID。 |
| 一段自然简介、可安全展示的数量、公开参考资料 | `feishu-library-editorial.json`。先写内容是什么和适合做什么，必要时写清范围。 |
| 服务器登记与证据 | 现有 `resource-mapping.json` 和上游采集资料。平台按登记身份生成阅读视图。 |
| 大类和细分类的定义 | `library-taxonomy.json`。名称可以修订，现有分类 ID 供链接与程序继续引用。 |

Agent 可读 `GET /api/platform/library`。`kind` 选择 `dataset` 或 `model`，`category_id` 和 `subcategory_id` 对应 `categories`。`role` 描述原包、集合、派生特征、模型等资料形态，`status` 记录来源进展。服务器条目沿用 `asset_id` 并提供 `registry_id` 与 `api_url`。飞书条目沿用飞书记录 ID，可用 `source_url` 查原表，用 `reference_url` 查发布者资料。

数量必须带单位与范围。同一资源可能同时出现在服务器目录和飞书台账，统计独立资源前先核对版本和来源。飞书登记的个人授权、申请材料及私有盘路径留在原表。使用者引用自己可访问的证据和版本。

业务成员可直接更正飞书分类和进展。门户优先读取同步缓存，也可读取随版本提供的快照。维护者可用 `tools/prepare_feishu_library.py` 和最新的四列导出重建快照，参数见 `--help`。脚本用导出时间更新台账读取日期，从现有快照继承同一记录、同一标题和同一数量的来源日期。新增或修改的数量需要另行核对来源日期，缺失时显示「未注明」。
