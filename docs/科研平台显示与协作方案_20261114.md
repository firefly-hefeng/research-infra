# 科研管理平台显示与协作方案

首页把「团队在研究什么、已经做到哪里、现在可以接着做什么」放在一起。以现有研究方向 ID 串起成果、数据、文献、成员进展和实验记录。成员从同一个方向进入，逐层打开证据或运行方案。各模块保留自己的维护入口。

## 1. 页面与阅读顺序

| 页面 | 首屏优先显示 | 展开后可查 |
| --- | --- | --- |
| 研究总览 | 研究方向搜索、五个已有方向的星图与列表、最近成果、待协作事项和下一步 | 方向页、已有成果档案、研究文书 |
| 研究方向 | 研究问题、最近核对日期、当前结论及验证范围、阻塞和下一步 | 按日期排列的研究证据、数据与文献、实验结果、成员和周报来源 |
| 数据与模型 | 五组资料大类和待核对入口，显示条目数与覆盖范围 | 原分类、小类、数据集或模型、名称/用途/来源筛选及详情 |
| 文献与文书 | 方向相关论文和项目来源。团队文书提供目录、阅读摘要和原文 | 题录、已核验卡、DOI、引文页码、原文访问条件 |
| Agent 实验 | 输入研究方向，查看已有研究与差距、可用数据和建议方案 | 数据预检、运行参数、预算、日志、产物与可复核结果 |

进度总览以研究问题为行，显示**已核查的结论 → 当前证据缺口或阻塞 → 下一步**。打开一行后按真实日期展示证据时间线。事件只保留「发生时间、做了什么、证据链接」，需要交接时再加负责人。只有方向文书明确记录了里程碑，才画对应节点。日报和周报显示成员贡献、需要协助与下周安排，提交覆盖率留在成员视图。方向当周没有新证据时显示最近核对日期，有空缺的条目直接标记待补。

### 视觉语言

采用深空背景、醒目的标题和克制的指标排版。NASA 首页的主题导航和搜索、NASA Science 太阳系页面从全景到行星详情的结构、NASA Eyes 的探索方式分别用作导航、图文层级和交互参考。原型的星场及行星为原创生成图像，五个节点对应五个真实方向。节点大小、颜色和位置只用于定位与区分。表现进展的文字独立于星图，研究关联要有对应证据才连线。手机默认可用方向列表，星图可以主动打开。桌面提供可点击、可用键盘的节点和列表。保留清晰焦点、短标题、无自动旋转，读正文时降低装饰密度。 [NASA 首页](https://www.nasa.gov/) · [NASA Science 太阳系](https://science.nasa.gov/solar-system/) · [NASA Eyes](https://eyes.nasa.gov/apps/solar-system/)

## 3. 管理与协作

| 对象 | 人员职责 | Agent 能做的事 |
| --- | --- | --- |
| 数据与模型 | 来源负责人在飞书维护分类与申请进展，在服务器目录保留资产 ID、版本和使用说明。更新规模时注明单位、范围和证据日期 | 同步已有四列、检查链接和版本、生成简介草稿。缺许可或版本时标待核对 |
| 文献 | 维护者整理入库，对已读证据补 DOI、页码及适用范围。团队笔记沿用当前共享模式 | 搜索题录和有权读取的原文。引述保留页码。权限不足时仅引用可读题录，并标明依据层级 |
| 研究方向与进度 | 成员继续提交日报和周报，可附方向链接。方向负责人维护短 Markdown，核对结论、阻塞和下一步。委员会处理跨方向争议、授权和正式发布 | 归集带方向 ID 或方向链接的条目、发现冲突、出草稿。无法归类的条目保留原出处与待核对提示 |
| 文书与接口 | 文书保留短 README 与正式原文，稳定链接供成员和 Agent 共用 | 检查入口、显示状态与证据是否一致，按需生成可回查的摘要 |

每个方向沿用 `id`、标题、最近核对、研究问题、进展、下一步、来源与范围，负责人可留空。团队进度可用现有周报修订号和来源哈希回查。单次实验另有运行记录。日常更新由成员和方向负责人直接完成，采用现有权限和修订方式。

## 4. 从研究方向到实验

1. **查找先验。** 接收自然语言查询，按研究任务、语种、人群、模态和预期输出匹配现有方向。返回内部成果、相关数据或模型、论文或题录以及证据缺口。低置信度时列出候选方向，由成员选定或新建草稿。资料和论文的内容作为参考信息读取。
2. **拟定方案。** 写清研究问题、假设、数据版本与使用条件、按参与者分组的切分、对照基线、指标口径、运行预算与停止条件。将每一项同原证据相连。数据路径和可读性通过预检确定。
3. **执行预检与试跑。** 先试点资料可用性、标注完整性、切分泄漏检查，以及合成或已获准小样本的基线试跑。已授权且预算内的受控任务可直接运行。执行端使用真实团队身份，按资源 ID 解析允许的版本，运行登记过的模板并记录预算。受限资料、新用途、外部传输和高资源作业依据现有权限交给相应负责人。计算监控继续提供观测值，资源配额和队列以执行端为准。
4. **回写证据。** 每次运行记录方向 ID、运行 ID、操作者、数据和切分版本、代码与配置、样本与排除规则、指标与范围、结果、日志与产物链接。失败也保留原因和下一步。Agent 可生成周报及方向进展草稿，成员可修改。正式成果由方向负责人核对后发布，团队可见的摘要使用获准内容。

**试点示例。** 输入「中文自由对话的抑郁程度预测」。先列出 DepAlign 的 DAIC 英文回顾测试（47 名参与者，PHQ-8 原始分 MAE 3.694、RMSE 4.552），以及 MMPsy 中文开发集（MAE 7.806／100，量纲为 `100 × PHQ-9／27`，独立测试待完成）。两项目分开展示人群、切分和量纲。CMDC 在飞书台账中记录为已获领取口令，公开页面记录八个分包，预检需要确认已授权的本地版本、标注与评估范围。首步运行预检，条件满足后再做小样试跑。中文自由对话外部验证仍属下一步。 [DepAlign 方向原文](../research-progress-next/deploy/directions/depalign-final.md) · [MMPsy 方向原文](../research-progress-next/deploy/directions/mmpsy-v3-ensemble.md)

## 5. 自动更新与实施顺序

- **复用现有读取能力。** 使用 `/api/agent/manifest` 发现门户接口，`/api/platform/research` 读取人工审核成果，`/api/platform/library` 读取资料和模型，`/api/resource-mapping/{registry_id}` 回查登记证据，`/api/platform/literature` 查资料关联来源，`/papers/api/state` 在文献服务权限内查题录和卡片。进度继续读 `/progress/api/directions/{id}` 和 `/progress/api/team/{week}`。
- **按变化更新。** 数据同步沿用现有飞书缓存，面板显示最近成功读取时间。方向、文书和成果的来源版本有变化时重建检索索引与摘要，并链接前一版本。周报沿用现有接收与汇总机制。实验结束后生成一次增量草稿，重复任务按输入版本与运行请求去重。页面同时显示最近成功记录、失败原因与重试入口。
- **依次交付。** 第一批完成总览、方向证据视图和资料分类导航，连接现有接口。第二批上线只读方向检索、证据包和可编辑方案，验证已有结论、待证假设与空结果都能准确显示。第三批接入独立受控执行端和专属实验记录，先验收授权检查、预算限制、取消、失败恢复及回写草稿，再扩大可执行模板。当前半小时平台维护任务继续用于逐模块改进。实验作业使用单独的事件触发和队列。

**验收任务。** 在桌面和两种手机宽度用键盘和触控完成「总览找发现 → 查范围及原文 → 找同方向资料 → 生成方案」。核查覆盖率不充当完成率、缺数据可解释、列表与星图选择一致、跨模块可返回、延迟与失败可重试。试点运行以已登记的小样本完整闭环为准。

原型数据来自工作区的方向文书、人工审核成果与目录快照。方向页的里程碑来自成果档案。Agent 原型使用本地快照按关键词筛选相关方向，并提供方案草稿。正式执行入口待接入。
