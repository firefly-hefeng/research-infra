一 当前接口与目标接口的边界

当前门户在线/api/openapi.json已读取并原样保存，见现有门户OpenAPI。下面/api/v1为建议新增的统一契约，全部尚未部署，不能据此调用服务器写入。进度和文献旧模块另列实际路由；两模块本地处理文件与生产文件SHA256一致，门户源文件与当前本地不同，因此现有门户能力以本次在线契约与只读响应为准。

目标契约采用OpenAPI 3.1.0及JSON Schema；错误响应采用RFC 9457 Problem Details。机器文件：OpenAPI YAML、OpenAPI JSON、事件信封Schema。

三 目标接口共用规则

项目约定
版本和路径https://rmp.wuwangwo.top/api/v1为规划前缀；旧/api、/progress/api和/papers/api保持兼容，先新增适配层再逐项切换。
身份浏览器使用具名HttpOnly/Secure会话；服务使用短期最小权限Bearer。author/actor由服务器取得，不信任请求里的姓名。Cookie写请求还需CSRF及Origin校验。
权限先认证，再检查项目角色、对象可见性和内容用途授权。看得到条目、能读取路径、允许某用途使用，是三层判定。对无权对象可统一404以减少泄露。
数据JSON UTF-8；未知为null，0为已知零；JSON拒绝重复键、未知请求字段和非有限数；分页cursor+limit，默认50，上限200；时间RFC3339带时区。
修订读取单对象返回强ETag；PATCH和决策/确认/封存/审批/发布请求携带If-Match，对应被变更主对象；缺失428、旧修订412。
幂等POST/PATCH必须Idempotency-Key；以主体、方法、规范路由和键去重，保存请求摘要与原响应至少7天；同键异体409。不可变resource/version及提交摘要另设永久唯一约束。
状态同步创建201，读取/变更200；异步202+Operation+Location。202只表示受理；GET operation成功且资源发布回执存在才可显示已发布。
错误application/problem+json；统一type/title/status/code/request_id/retryable，可附field错误；不返回密钥、原件内容或其他用户路径。
写入客户端只提供受控ID及相对路径；storage_id映射服务器根，拒绝..、绝对路径和跨界链接。路径登记本身不复制文件；只有白名单发布执行器能写正式库。
追溯响应X-Request-Id；写入记录actor、对象修订、动作、时间、证据摘要和结果；日志不含凭据、受试者标识或完整训练命令。

四 核心状态机与跨中心事务

数据增补沿用现有状态：submitted → validating → needs_information / review_required / ready → publishing → published，失败为failed。未知许可保持待补；重验或重计划使旧审批失效；publishing/published禁止重验；目标已有且回执不完整时进入review_required，不盲目续写。

任务为todo、active、in_review、accepted、blocked、cancelled；里程碑accepted必须由独立审核者根据验收项决定。报告为uploaded、parsing、needs_review、confirmed；报告confirmed不改变任务accepted。运行结果为succeeded、failed、cancelled；即使运行succeeded也不表示科研结论通过。

每个中心只写自己的事实。统一对象更改与outbox事件在同一数据库事务内提交；消费者按event_id去重，按aggregate_revision拒绝旧事件，失败可重试。采用至少一次投递，不宣称跨服务exactly-once。发布文件与SQLite无法成为一个数据库事务，沿用不可变发布回执及恢复对账；增补发布后资料卡待补与目录投影延迟均显式显示。

事件只带稳定ID、修订、发生时间及证据ID。各中心经受权接口读取详情，避免把路径、报告原件或受限许可全文广播给所有订阅者。第一阶段用本机outbox轮询即可。

业务不变量运行时必须核对
摘要协议现有2.0 content_digest = SHA256(UTF8(submission_sha256 + 换行 + manifest_sha256))，末尾无换行。manifest沿用现有逐文件原始字节协议。目标plan_sha256对kind、resource_id、version、content_digest、policy_revision、metadata_revision六个字段组成的对象计算：键按字典序、JSON紧凑分隔、ensure_ascii=true、UTF-8、无末尾换行；客户端回传服务器给出的摘要，不自行重写计划。
项目和依赖任务的milestone必须属于同一project；依赖图拒绝自环和环；审核者未指定时继承里程碑审核者；权重为正、基线修订一致。项目跨引用不重复计入验收分母。
发布门禁增补published只证明payload按协议落盘，允许team_card_pending；不等于科研版本released。科研版本转released才要求dataset的DataProfile或model的ModelProfile、质量与用途依据、正式资料卡和内容回执，经独立审核。物理发布仍须许可、目录归属、政策、容量与摘要门禁。resource/version永久唯一。
计划和审批plan_id须属于当前submission；审批者不能是提交者；批准摘要、内容摘要、目标、metadata_revision和policy_revision必须与执行时一致。政策变化或内容变化需重新计划审批。
认证与重放即便命中幂等记录，也先校验当前认证和对象可见范围；撤权后不得利用旧幂等键取回敏感响应。分页cursor绑定筛选、排序、可见范围与快照时间，跨范围复用拒绝。
运行与统计所有输入版本授权均对执行者和项目用途有效；实验划分摘要与run一致；指标必须标明split、计数和聚合；只能比较协议兼容指标。
轮询与重试异步操作建议1至5秒退避轮询；只对retryable=true或明确网络失败重试，复用原Idempotency-Key。内容漂移、授权不足或目标冲突不能自动换键绕过。

七 关键调用与冲突示例

所有ID与摘要为虚构示例。先读取对象取得ETag；下面审批绑定现有主对象修订与不可变plan摘要。不得对当前生产路由直接发送这些写请求。

POST /api/v1/submissions/sub-example-001/approvals
Authorization: Bearer <service-token>
Idempotency-Key: approval-example-20261113
If-Match: "rev-3"
Content-Type: application/json

{
  "plan_id": "plan-example-001",
  "plan_sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "content_digest": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
  "rights_decision": "management_authorized_team_use",
  "rights_evidence": [
    {
      "evidence_id": "ev-example-rights",
      "relation": "approval"
    }
  ],
  "reason": "仅批准所列主体与研究用途 不含外发"
}

审批成功后由publisher_service提交publish；受理返回202与operation_id，客户端轮询，不立即标绿。若目录内容在审批后变化，返回CONTENT_DRIFT并阻止发布；同目标版本已有不同内容返回409，不覆盖。

{
  "type": "https://rmp.wuwangwo.top/problems/content-drift",
  "title": "内容与批准摘要不一致",
  "status": 409,

  "request_id": "req-example-001",
  "retryable": false,

}

周报保持multipart原件上传；author来自登录身份，不接受客户端替他人填写member_id。上传保存201后报告状态为uploaded/parsing；本人confirm关联证据后才进入确认汇总，但里程碑仍需单独验收。

八 兼容与实施门禁

  • 旧asset_id、registry_id、paperlib内部ID、member_id、飞书record_id全部保留在外部标识映射；历史报告标记声明身份，不伪造认证记录。
  • 第一个适配器只读现有门户、文献与进度状态；通过正式接口或受控后台操作逐项接入写能力，禁止由前端跨库直接更新SQLite。
  • 正式版本README、manifest与发布回执保留为内容证据；新增协作数据库不覆盖这些依据。目标元数据更新接口必须同时生成审计和修订后投影。
  • 先验收逐人身份、Cookie来源/CSRF、对象权限、用途授权、If-Match、幂等、目录边界、摘要漂移、版本冲突、异步恢复和事件重放。
  • 上线前运行消费者与提供者契约检查；当前文档的结构校验只证明接口文件内部一致，不等于服务器已通过业务或压力测试。
事实以来源的观察时间和检查范围为准；方案、接口与流程建议须实施并验收后才视为平台能力。本文档包未改动生产服务、目录、权限或训练任务。
